## PDR-009: Google Tasks Bidirectional Sync Strategy

### Status

**Proposed**

### Date

2026-08-24

### Owner

User/AI collaboration

### Category

Feature

### Feature-Area

core

### Context
**Problem/Opportunity:**
Tasks created or modified in Google Tasks must appear in the local consolidated view, and tasks created locally must sync back to Google Tasks. Bidirectional sync ensures a single source of truth across both systems.

**Market Forces:**
- Users expect real-time task updates across devices
- Google Tasks API supports incremental sync via sync tokens
- Local-first architecture requires SQLite as primary data store

### Decision
**Decision Statement:**
Implement polling-based bidirectional sync with Google Tasks API sync tokens for incremental updates, using SQLite as the authoritative local store.

**Rationale:**
Polling with sync tokens is Google's recommended approach for task sync. It's simpler than webhooks (which Google Tasks doesn't support) and provides reliable eventual consistency. SQLite as primary store maintains the local-first architecture.

### Consequences
#### Positive
- Incremental sync reduces API calls and improves performance
- Local-first architecture means app works offline
- Sync tokens provide reliable change detection

#### Negative
- Polling introduces latency (user changes not instant)
- Requires handling of sync token rotation and conflict detection

#### Risks
- Sync token invalidation → full re-sync fallback with exponential backoff
- Race conditions between local and remote edits → timestamp-based conflict resolution

### Success Metrics
| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| Sync latency | <30 seconds | Time from Google change to local view update |
| Sync reliability | 99%+ | Successful sync cycles without errors |
| Offline functionality | Full | Tasks modifiable offline, synced on reconnect |

### Alternatives Considered
#### Option B: Webhook-based Real-time Sync
**Description:** Push notifications from Google when tasks change.
**Trade-offs:** Lower latency, but Google Tasks doesn't support webhooks.

#### Option C: Full Sync on Every Launch
**Description:** Download all tasks each time app starts.
**Trade-offs:** Simpler implementation, but slower startup and higher API usage.
