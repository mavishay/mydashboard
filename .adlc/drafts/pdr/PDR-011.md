## PDR-011: Google Tasks Conflict Resolution

### Status

**Proposed**

### Date

2026-08-24

### Owner

User/AI collaboration

### Category

Feature

### Feature-Area

core

### Context
**Problem/Opportunity:**
When a task is modified both locally and in Google Tasks before sync occurs, a conflict arises. The system must resolve conflicts deterministically to prevent data loss.

**Market Forces:**
- Google Tasks API provides `updated` timestamp for conflict detection
- Local-first architecture means local changes should be authoritative
- Users expect their most recent action to win

### Decision
**Decision Statement:**
Use last-write-wins with local timestamp as authority. When conflicts occur, the most recent modification (based on `updated` timestamp) takes precedence, with local changes winning ties.

**Rationale:**
Last-write-wins is the simplest deterministic resolution. Local timestamp authority aligns with local-first architecture and user expectation that their immediate action takes effect.

### Consequences
#### Positive
- Deterministic resolution, no user intervention required
- Local-first behavior: user's immediate changes always take effect
- Simple implementation, easy to reason about

#### Negative
- Potential silent data loss if user modifies task in both places
- No merge capability for simultaneous edits to different fields

#### Risks
- User confusion when remote changes are overwritten → display conflict resolution notification
- Timestamp granularity issues → use millisecond precision for Google API timestamps

### Success Metrics
| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| Conflict resolution | 100% | All conflicts resolved without errors |
| User satisfaction | 90%+ | User feedback on sync behavior |

### Alternatives Considered
#### Option B: Manual Conflict Resolution
**Description:** Prompt user to choose which version to keep.
**Trade-offs:** Prevents data loss, but adds friction and complexity.

#### Option C: Field-level Merge
**Description:** Merge changes to different fields automatically.
**Trade-offs:** Preserves more data, but complex to implement for all task fields.

### Constitution/Vision Alignment
| Principle | Alignment | Notes |
|-----------|-----------|-------|
