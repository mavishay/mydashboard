## PDR-003: Automation Engine: n8n as Internal Plumbing

### Status

**Completed**

### Date

2026-08-23

### Owner

User/AI collaboration

### Category

NFR

### Feature-Area

system

### Context
**Problem/Opportunity:**
Spec mandates self-hosted n8n but did not define whether users may edit workflows. True webhooks also need public reachability — impossible for localhost n8n without tunnels, so v1 reality is API polling regardless.

**Market Forces:**
- n8n ecosystem growth validates workflow-engine reliability
- Competing tools hide automation entirely; extensibility differentiates only when exposed

### Decision
**Decision Statement:**
Run n8n in Docker as mandatory internal infrastructure for polling, LLM orchestration, and action dispatch. Hide the n8n editor from users; the app UI is the only surface. v1 uses API polling every N minutes; webhooks deferred.

**Rationale:**
Production-grade retry/scheduling semantics without building them; hidden editor keeps UX coherent while preserving the option to expose workflows later.

### Consequences
#### Positive
- Battle-tested scheduling/retry for free
- Optionality preserved to expose the editor post-v1
- Clean separation: app owns UX, n8n owns orchestration

#### Negative
- Docker is a hard prerequisite alongside Electron
- Polling latency up to N minutes for "push-like" behavior

#### Risks
- Install friction kills adoption → ship docker-compose profile + in-app health-check wizard
- Silent n8n failures → surface engine heartbeat in the app status bar

### Success Metrics
| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| Engine heartbeat green during active sessions | >99% | Local health log |

### Alternatives Considered
#### Option A2: Expose n8n editor as a feature
**Description:** User-editable workflows as selling point.
**Trade-offs:** Extensibility moat, but UX fragmentation; deferred to post-v1 based on demand.

#### Option B: In-app scheduler (BullMQ/node-cron)
**Description:** Scheduling inside Electron main process.
**Trade-offs:** Single-binary simplicity but rebuilds scheduling logic and loses connector ecosystem.

#### Option C: Hybrid internal scheduler + optional n8n
**Description:** Core sync internal; n8n opt-in connector.
**Trade-offs:** Smooth default install but two integration surfaces to maintain.
