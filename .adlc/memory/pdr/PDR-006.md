## PDR-006: V1 Success Metrics

### Status

**Completed**

### Date

2026-08-23

### Owner

User/AI collaboration

### Category

Metric

### Feature-Area

core

### Context
**Problem/Opportunity:**
No success criteria existed. The "silent by default" positioning makes notification precision existential: one false urgent ping destroys user trust in the entire product.

**Market Forces:**
- W4 retention for indie productivity tools hovers near 30%
- OSS projects live or die on first-run experience

### Decision
**Decision Statement:**
Adopt four v1 metrics: notification precision ≥90%, auto-triage coverage ≥70%, setup completion <15 minutes, W4 retention ≥40%. All measured via opt-in anonymous telemetry plus local logs.

**Rationale:**
Precision-first ordering reflects the trust thesis; the setup metric directly attacks the Docker-prerequisite weakness identified in PDR-003.

### Consequences
#### Positive
- Objective kill/pivot signal by month 2
- Precision metric enforces the core promise
- Opt-in telemetry reinforces OSS trust posture

#### Negative
- Telemetry consent flow must be built
- Coverage metric could incentivize over-aggressive rules if gamed

#### Risks
- Low telemetry opt-in skews data → pair with a local-only stats view users can inspect and share manually

### Success Metrics
| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| Notification precision | ≥90% | In-app thumbs up/down per notification |
| Auto-triage coverage | ≥70% | Local DB: rule-driven actions vs total emails |
| Setup completion | <15 min | Onboarding funnel (opt-in) |
| W4 retention | ≥40% | Anonymous weekly ping |

### Alternatives Considered
#### Option A: Vanity-first metrics (stars/downloads)
**Description:** Optimize reporting around growth vanity numbers.
**Trade-offs:** Encouraging optics but uncorrelated with whether the product keeps its promise.

#### Option B: Growth-first metrics
**Description:** Targets on stars, DAU, and community size instead of promise-keeping quality.
**Trade-offs:** Motivating for launch publicity, but incentivizes breadth over the trust thesis; precision failures would show up late as churn rather than early as data.
