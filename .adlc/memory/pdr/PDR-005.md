## PDR-005: Primary Persona: Multi-hat Consultant with Unlimited Accounts

### Status

**Completed**

### Date

2026-08-23

### Owner

User/AI collaboration

### Category

Persona

### Feature-Area

core

### Context
**Problem/Opportunity:**
The Personal/Work/Client three-account framing implies a specific user whose daily pain justifies installing a unified dashboard over existing single-account apps.

**Market Forces:**
- Superhuman ($30/mo) targets executives; Missive targets teams — solo multi-account consultants are underserved
- Consultants handling client confidentiality cannot casually use cloud aggregators

### Decision
**Decision Statement:**
Primary persona: freelancer/consultant aged 25–45 running 3+ mixed-provider inboxes (Gmail + M365), using TickTick/Google Tasks, comfortable with Docker and BYOK. No hard account cap in v1.

**Rationale:**
Matches the spec's own framing; the pain is daily and acute; Docker/BYOK are non-issues for this user; unlimited accounts removes the most common first-week objection ("what about my fourth inbox?").

### Consequences
#### Positive
- Sharp design target for every UX decision
- Unlimited accounts is architecturally cheap (N tokens in SQLite)
- Explicit anti-persona prevents scope drift toward corporate employees

#### Negative
- Corporate employees (larger market) are out of scope for v1
- Unlimited accounts enlarges the OAuth review surface

#### Risks
- Gmail restricted-scope verification burden → start in testing mode; publish privacy policy early
- TickTick API informality → isolate behind adapter interface so swap is cheap

### Success Metrics

### Alternatives Considered
#### Option B: Power-User Employee
**Description:** Work + personal accounts, corporate M365 managed device.
**Trade-offs:** Bigger market, but managed-device policies often block local mail readers.

#### Option C: Solo Founder / Indie Hacker
**Description:** Lighter client-account needs.
**Trade-offs:** Louder community channel but weaker daily pain than consultants.
