## PDR-002: AI Execution: Bring-Your-Own-Key Cloud-First

### Status

**Completed**

### Date

2026-08-23

### Owner

User/AI collaboration

### Category

Feature

### Feature-Area

system

### Context
**Problem/Opportunity:**
Spec said "pluggable interface supporting external APIs or local Ollama" without a default posture. The default determines the privacy story, cost model, and triage quality — and it interacts directly with the product's privacy positioning.

**Market Forces:**
- Users increasingly distrust vendors reading their mail; BYOK shifts the trust decision to the user
- Cloud LLMs dramatically outperform local small models on classification quality

### Decision
**Decision Statement:**
Cloud LLM providers (OpenAI/Anthropic) are the default execution path using user-supplied keys (BYOK). Full email payloads are sent when cloud mode is enabled. Strict connectivity requirement: AI features need a working provider connection.

**Rationale:**
Best triage quality out of the box; no vendor middleman holds keys or aggregated data; the user consciously grants provider access under their own billing.

**Constitution Override Justification** (Security by Default, resolved 2026-08-23):
Override justified — payload destination is chosen and billed by the user (BYOK); no aggregation server exists; onboarding displays the payload policy as an explicit consent step. Revisit a truncation option post-v1.

### Consequences
#### Positive
- Best-in-class classification quality from day one
- No central server becomes a honeypot of user mail
- Cost transparency lives entirely in the user's provider account

#### Negative
- Full payloads leave the machine — the naive "privacy-focused" claim does not survive this and must be reframed as "no vendor middleman; you own the key"
- Quality collapses if a user has no API budget

#### Risks
- Provider reads sensitive client email → document payload policy prominently at onboarding; offer truncation setting post-v1
- API key theft from local DB → encrypt keys at rest; prefer OS keychain storage

### Success Metrics
| Metric | Target | Measurement Method |
|--------|--------|-------------------|
| AI-classified emails meeting user expectations | ≥85% after 2 weeks | Thumbs-down rate on triage actions |

### Alternatives Considered
#### Option A: Local-default (Ollama first)
**Description:** Local model default, cloud opt-in.
**Trade-offs:** Maximum privacy, weaker quality, GPU requirement blocks many users.

#### Option B: Local-only
**Description:** No cloud integration at all.
**Trade-offs:** Absolute privacy story; quality floor too low for core triage promise.

### Constitution/Vision Alignment
| Principle | Alignment | Notes |
|-----------|-----------|-------|
| Security by Default | ⚠️ Deviation | Full payload to third-party LLM accepted deliberately; encryption of keys at rest is non-negotiable |
| Zero Trust Security Model | ✅ Compliant | No implicit trust even of local components; explicit user grant required |
